# 02 - Top-rated GitHub repos vs. huntkit gaps

Researcher: Ryan | Date: 2026-10-10 | Source: GitHub MCP search (stars sort) + README reads (raw.githubusercontent). Stars/last push/license come from the GitHub API on 2026-10-10. A "~" marks a value taken from `updated_at` because no full metadata fetch was made.

**Baseline (huntkit today):** a case lifecycle with 22 `q-*` commands; 3 skills (osint, structured-analysis, leak-record-classifier); 2 MCP servers (osint-infra: whois/dns/wayback; threat-intel: VT/URLhaus/ThreatFox/crt.sh); paid search/scrape wrappers (Exa, Jina, Tavily, Bright Data, Apify, Perplexity); evidence capture (Wayback + archive.today + PDF + SHA-256).

**Correction to the capabilities note:** huntkit does mention `maigret`, `ghunt` and `holehe`, but only as ad-hoc CLI lines in `commands/q-osint.md`, `q-collect.md` and `skills/osint/SKILL.md`. Nothing installs them, wraps them, checks them or turns their output into EV records. So the gap is "no structured integration", not "unknown tool".

Effort scale: **S** < 1 day, **M** 1-3 days, **L** > 3 days.

**Licensing notes:** GPL/AGPL tools (holehe, phoneinfoga, theHarvester, bbot, firecrawl, exiftool, GHunt) should be **invoked as external processes or services**, not vendored into huntkit's tree. MIT/Apache tools (maigret, cytoscape, splink, GLiNER, langextract, crawl4ai, FtM, yente, geo-sleuth) can be vendored with NOTICE files, following the structured-analysis precedent.
